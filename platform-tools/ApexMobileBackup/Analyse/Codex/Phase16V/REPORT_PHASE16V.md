# Phase16V - DolphinUpdater method-caller provenance

## Executive result

Phase16V recovered four valid external direct callers into the exact protected
CheckUpdate FDE start. Three pass their function argument 0 as the owner; the
fourth loads the owner from `selected GameUpdateMgr entry + 0x38`. Exact source
identifiers classify these paths as StartUpdate, source-update completion,
update-success handling, and SkipAppUpdate. Their CFG is event-driven.

The OnNoticeInstallApk and first-extract-success callbacks independently load,
null-test, and pass the same exact field, `DolphinCallback+0x08`, to owner
methods. This promotes that location as confirmed persistent owner storage.
Shutdown has no external direct caller beyond its confirmed `this-0x28`
adjustor, so CheckUpdate/Shutdown storage convergence remains unknown.

The exact callback field writer axis proves only the callback initializer's
null store at Ghidra `0x0a2a4044` / ELF `0x0a1a4044`. No non-null assignment,
pointer source, or allocation was recovered. Class semantic identity remains
probable because the persistent callback field does not converge with a
CheckUpdate or external Shutdown storage source.
