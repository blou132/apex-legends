# Phase16R - retained Dolphin bootstrap-state correlation

Phase16R correlated the retained Phase15U, Phase16I, and Phase16M evidence
against the exact client CheckUpdate continuation without touching a device or
running Apex.

The bounded W23 helpers resolve to the Unreal packaging setting
`bUseIFSFile`: an unresolved/absent setting produces zero, otherwise the value
is parsed as a boolean. No retained marker exposes that result.

The direct listing also corrects the prior `owner+0x45` model. A zero flag
uses a null fourth Init argument. A nonzero flag logs the first-extract mode,
prepares a different fourth argument, and rejoins the same slot-`+0x10` Init
dispatch. The flag is therefore an Init-mode selector, not an absolute Init
blocker. The first-extract-success callback later clears it.

Phase15U confirms provider Dolphin Init through the one-way
`CVersionMgrImp::Init` implication. The exact `DolphinUpdater+0x1f0` client
dispatch is probable for that run, not confirmed, because acquisition and the
dynamic target remain unresolved. Phase16I and Phase16M retain Puffer activity
but no Dolphin/version-manager witness. The earliest observable difference is
Init execution; no retained evidence identifies one concrete pre-Init state.
