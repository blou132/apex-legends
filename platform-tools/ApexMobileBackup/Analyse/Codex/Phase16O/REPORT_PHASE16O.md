# Phase16O - CreateDolphin callsite reachability

## Executive result

Phase16O reconstructed a 206-block CFG for the exact FDE
`0x05a311a8...0x05a31ca8`. A syntax-only graph reaches the sole
`CreateDolphin` call at `0x05a314cc`, but only by allowing the imported
`std::__throw_length_error(char const*)` at `0x05a3144c` to return. That helper
is noreturn. The noreturn-aware graph ends before the factory region, and no
direct side entry, computed branch, jump table, LSDA landing pad, or cleanup
edge enters it.

The factory call remains correctly attributed: raw BL decoding, PLT, GOT,
`.rela.plt`, and dynsym still identify `CreateDolphin`. Its post-call register
shape resembles a string constructor, but the actual next branch again targets
`std::__throw_length_error(char const*)`; the factory result in `x1` is ignored.
The surrounding function contains the previously observed systematic
one-physical-PLT-entry mismatch. Its origin is unknown, so this report does not
label it as obfuscation, anti-cheat, or a deliberate decoy.

The bounded upper chain is a post-extraction path-bundle builder reached from
`DolphinCallback::OnDolphinFirstExtractSuccess` when its owner pointer is
non-null. It is not promoted to bootstrap ownership. The exact static factory
reference is classified as unreachable dead code and has no value as a future
runtime breakpoint target. The ptrace gate remains closed.
