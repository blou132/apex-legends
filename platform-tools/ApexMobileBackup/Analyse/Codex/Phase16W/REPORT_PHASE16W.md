# Phase16W - DolphinCallback provenance and owner assignment

## Executive result

Phase16W resolves the exact provider callback ABI. In
`GCloudDolphinImp::Init` (`FUN_005458a0`), entry `X5` is null-tested and stored
unchanged at provider `+0x10`. Mapping this position to the real client Init at
ELF `0x05a2f0ac` proves that the callback pointer comes from
`[DolphinUpdater+0x1f8]`. The provider later dispatches the same key callback
slots as the known libUE4 DolphinCallback table.

This upgrades owner `+0x1f8` from a probable related interface to a confirmed
callback pointer. It does not prove that the concrete pointed object has table
ELF `0x0ae55170`, because the table installation and the non-null writer of
owner `+0x1f8` remain before the readable CheckUpdate frontier. The known
class initializer still contributes the only exact `callback+0x08` write: a
null initialization at ELF `0x0a1a4044`. No non-null owner assignment is
reachable.

The independent `SkipAppUpdate` control resolves the selected GameUpdateMgr
entry through an exact collection lookup and confirms owner consumption from
entry `+0x38`. Its writer is likewise unavailable from the proven path, so the
two storage locations cannot be converged without a forbidden global scan.
