# Phase16J - offline CVersionMgr trigger and thread resolution

## Executive result

Existing evidence and a bounded read-only Ghidra pass resolved the direct
trigger chain and historical executor without launching Apex. `CreateDolphin`
constructs `GCloudDolphinImp`; its Init creates a manager, builds the update
configuration, and invokes manager slot `+0x10`, whose wrapper is the sole
direct caller of `CVersionMgrImp::Init`. CheckAppUpdate is a separate slot.

The retained Phase15U log directly maps the Init witness to `Thread-10` in the
same run, raising thread confidence to HIGH. Phase16I selected that thread
correctly. Its no-trap result is explained by the missing Dolphin bootstrap
branch, not by a failed breakpoint or wrong thread.

Phase15U entered the full Dolphin version path near +118 s. Phase16I instead
showed repeated Puffer activity without any version-manager or Dolphin action.
The best-supported explanation is a different bootstrap branch. The exact
upstream predicate selecting `GCloudDolphinImp::Init` remains unresolved;
AppData dependence is possible but unproven.
